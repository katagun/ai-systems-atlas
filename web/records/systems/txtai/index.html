txtai

The most complete answer to building an agentic system out of one local dependency rather than a database, an orchestrator, and a model server: the retrieval substrate and the agent loop are the same library and the same index, which is also why the record is filed as a framework rather than as a store.

Product boundary
One framework with two products: the repository's own words call the embeddings database "the key component", a union of vector indexes, graph networks and relational databases, while the feature list leads with agents, pipelines, and workflows built on top of it. This record follows the framework, on the Haystack and RAGFlow precedent, because the agents and workflows are the outcome a reader adopts it for; the database is what makes that outcome cheap. The vendor's txtai.cloud is described in the README as still being built and is not reviewed here.
