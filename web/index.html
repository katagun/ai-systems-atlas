Open-source systems, compared by what they actually are

Do not compare a coding workflow to a vector database.

Cognosaic separates product role from memory architecture, capture mode, lifecycle, and agent relationship—then scores each project for second-brain usefulness.

Primary role answers “what is the product?”
Architecture answers “how does it store and retrieve?”
Agent relation answers “where does memory live relative to the agent?”

A multi-axis model

One primary role. Several orthogonal traits.

A system can be an AI knowledge app that uses a vector index, runs locally, captures files, and exposes tools to agents. Those are different facts—not competing labels.

External agent memory

A separate library or service persists memory outside the agent runtime. Agents call it through an SDK, API, CLI, or protocol. Replacing the agent does not delete the memory. This improves reuse, but can create an opaque second source of truth.

Ambient capture

Passive collection of digital activity—screenshots, audio, active apps, window titles, or events—without deliberate note taking. It minimizes capture friction but creates severe privacy, noise, retention, and consent obligations.

Vector-based

Not a product category. It means embeddings are stored and searched by semantic similarity. Human PKM tools, RAG apps, agent-memory services, and ambient systems can all use vectors while remaining fundamentally different products.

Local-first operational memory

A brain that can explain where an answer came from.

Canonical Markdown records, append-only audit events, explicit supersession, a rebuildable SQLite index, and bounded cited context packs.
